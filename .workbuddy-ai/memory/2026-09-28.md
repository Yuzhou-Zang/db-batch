## 项目通读（只读，未改任何代码）

摸清了本仓库的真实定位：它是在 `dreammis/social-auto-upload`（多平台视频上传工具）基础上二次改造出来的
「AI 视频批量生成 + 去水印 + 发布」工作台，目录名已改成「豆包多账号批量生成视频」。

### 核心链路
1. `webui/`（aiohttp，端口 8765，入口 `start_web.py` → `webui/app.py:create_app`）提供本地管理台：
   账号池、任务池、定时/立即运行、运行日志。前端为 `webui/static/{index.html,app.js,style.css}`。
2. `webui/runner.py:TaskRunner` 是编排核心：`VIDEO_GENERATORS = {"doubao": DoubaoVideoGenerator, "dola": DolaVideoGenerator}`，
   `VIDEO_BLUR_HANDLERS = {"doubao": 加模糊.blur_video_inplace, "dola": dola_blur.blur_video_inplace}`。
   支持按账号并行（每账号同时 1 个任务）、额度用尽自动换号、内容违规申诉、失败重试。
3. 生成层：`doubao_video.py`（豆包 www.doubao.com，模型 Seedance 2.0 Fast）与 `dola_video.py`
   （即梦 Dola，模型 Dreamina Seedance 2.0 Fast，多一个时长选择）。两者都是 Playwright 驱动本机 Chrome
   （`conf.py:LOCAL_CHROME_PATH`）操作网页：上传参考图 → 填提示词 → 选比例/模型 → 提交 → 轮询 → 下载 mp4。
   异常分类：`QuotaExhaustedError`（当日免费额度用尽）/ `VideoGenerateFailedError`（可重试）/ `ContentBlockedError`（违规）。
4. 后处理：`加模糊.py`（豆包版，模糊左上+右下两个区域）与 `dola_blur.py`（Dola 版，只模糊右下），
   用 ffmpeg `boxblur` + `overlay` 盖掉平台水印，`blur_video_inplace` 原地覆盖。
5. 数据目录：`cookies/doubao|dola`（账号 cookie）、`data/accounts|tasks|runtime|trash`、
   `doubao_video_output`（默认输出）。删除采用移入 `data/trash` 的可恢复方式。

## 重大故障定位：提交环节从未成功（2026-09-28 排查）

### 现象
任务卡在"步骤7/7 等待视频生成"，日志无限刷「本轮没有新豆包回复，保持状态 waiting，继续等待。」
直到 20 分钟超时。浏览器里提示词仍留在输入框、比例弹层还开着，说明**消息根本没发出去**。

### 取证方式（可复用）
管理服务还在运行时，会话日志保存在内存里（`webui/runtime_log.py: SessionLogStore`，最多 5000 条），
可以直接拉取，不必依赖截图：
```
curl -s "http://127.0.0.1:8765/api/runtime/logs?after_id=0"
```

### 统计结论（13:44 服务启动 ~ 15:46）
| 计数 | 日志 |
|---|---|
| 6 | 步骤6/7完成（自称提交成功） |
| 6 | 提交后未出现安全确认弹窗 |
| **0** | 状态识别 / 任务已被豆包受理 / 检测到本次任务完成 / 已保存 |
| 161 | 本轮没有新豆包回复 |
| 6 | Page.goto 超时；6 次 ERR_CONNECTION_RESET；4 次开屏弹窗不可交互 |

即：**本次会话 6 次走到提交，0 次真正提交成功，0 个成品。**

### 根因
1. `doubao_video.py:_select_ratio()`（639-721 行）在"新版参数面板"分支里点完比例选项后**直接 return，
   从不关闭弹层**。旧版分支只在异常时按 Escape。于是 `步骤5/7` 结束后比例/时长弹层一直开着。
2. 紧接着 `步骤6/7` 的 `_submit_by_enter()`（833-838 行）只用 `input_box.press("Enter")` 提交。
   弹层此时占着键盘焦点，Enter 被弹层吞掉 → 没发送、弹层也没关。
   （`_fill_prompt` 之所以正常，是因为步骤4 在弹层打开之前。）
3. `_confirm_safety_notice_if_present()`（799-831 行）把"没等到安全确认弹窗"当成提交成功，
   于是 `_submit_by_enter` 从不报错，失败被静默吞掉。
4. `_download_video()`（945-1061 行）里"没有新回复"这一分支同时覆盖"正在生成"和"压根没提交"，
   所以只能干等满 20 分钟（`DOWNLOAD_TOTAL_WAIT_SECONDS`）。
5. 附带隐患：`_select_ratio` 里识别参数面板的正则要求标签含「自动/智能」，
   但选中后按钮标签会变成「9:16 · 10s」，不再匹配，后续再调用会走错分支。

### 修复方向（尚未实施）
- 步骤5 点完比例后主动关弹层（Escape / 再点一次设置按钮 / 点空白区），并确认已关闭。
- 步骤6 改为"优先点发送按钮（右下角蓝色箭头），Enter 作兜底"，提交后校验输入框已清空或出现新用户消息。
- 步骤7 增加快速失败：连续 N 轮（约 15~20 秒）仍无任何新消息 → 判定提交失败并重试，不要空等 20 分钟。
- `doubao_video.py` 与 `dola_video.py` 两份实现同源，改动需同步。
